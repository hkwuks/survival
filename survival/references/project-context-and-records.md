# 项目上下文与永久沟通记录

本文件适用于每一次涉及职场分析、决策或同事沟通需求的调用。用户已授权在本地永久保存其提供的姓名、原文和证据引用；记录服务于用户自己的事实保全，不是公开档案。

## 先读取项目设计与变更

以用户指定的项目根目录为唯一边界；未指定时使用当前工作目录。先识别项目自己的文档索引、目录约定和权威来源，再按相关性读取：

1. 项目提供的文档索引、贡献说明、知识库入口或任务路由文件（若存在），用它们定位权威资料。
2. 项目入口说明、需求、设计、架构、决策记录、变更日志、发布说明和当前任务资料；文件名、目录名与载体由项目自身约定，不预设 `README`、`docs/` 或 TaskFlow 结构。
3. 只提取会影响本次建议的版本、日期、状态、决策、接口、约束和变更；没有依据时明确说未知。

不递归读取项目根目录以外的位置，不把项目文件复制到沟通记录中。记录中只列出实际读取的路径和相关结论。

## 每次调用必须写入本地记录

首次调用时创建 `<project-root>/survival-records/`。每次调用在其中创建独立 Markdown 文件：

```text
survival-records/YYYY-MM/YYYY-MM-DD-HHMMSS-<short-topic>.md
```

文件必须包含：

```markdown
# 沟通需求记录

- 记录时间：
- 项目根目录：
- 调用主题：
- 已读取的项目文档与变更：
  - 路径 / 版本或日期 / 与本次问题相关的结论
- 提及人员与角色：
- 沟通需求：

## 用户原始输入

<逐字保留用户提供的原文；不要改写、删节或把推测写成事实>

## 证据与附件引用

- <用户提供或明确授权访问的原始材料路径、链接、编号或版本>

## 本次处理

- 选用的战役状态：
- 建议的下一步：
- 待核验事实：
```

姓名、原话、聊天内容和附件引用按用户提供的形式保留。记录永久保留，不自动删除、不自动归档、不自动脱敏。

## 不上传与安全例外

- `survival-records/` 必须位于 `.gitignore`；每次提交前检查它未被暂存。不得把其中内容提交、推送、贴入公开 Issue、PR、仓库或外部服务。
- 只记录用户提供或明确授权访问的材料；不通过越权登录、盗取、套话或导出无关数据补充内容。
- 不保存访问令牌、密码、私钥、会话 cookie 或其他凭据；若用户输入包含这类内容，记录“已收到敏感凭据，未保存”，并提示用户立即轮换凭据。
- 不因记录而改变原文件、时间戳、版本或公司系统中的证据。需要引用原件时记录路径、链接、编号或版本，而不是自动复制。
