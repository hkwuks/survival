# 可直接使用的模板

以下是可调整的例子，不是固定格式。根据关系、渠道、风险和用户语气取舍；关键结论是否另行书面确认应结合实际需要及成本判断。

## 书面：邮件、进度报告、工单和表格

### 任务确认

```text
主题：确认【任务/项目】目标、范围与交付安排

目标： 【】
本次包含/不包含： 【】 / 【】
验收标准： 【】
负责人和协作方： 【】
依赖与截止时间： 【】

当前风险： 【】。如需调整范围、优先级或资源，请在【日期】前确认；我会据此更新计划和验收标准。
```

### 会后纪要 / 进度更新

```text
结论： 【项目当前状态/本次决定】

已完成： 【产物、数据或链接】
已确认： 【事实和决策人】
下一步： 【负责人】-【交付物】-【截止时间】
风险/未决项： 【影响】；最晚需要确认的时间是【】

如上述记录有误，请告知需要修正的事项。
```

### 风险预警与决策请求

```text
主题：请确认【事项】的处理方案（最晚【日期】）

当前事实： 【数据/链接】
风险与影响： 【对时间、质量、成本或安全的影响】

方案 A： 【收益、成本、前提】
方案 B： 【收益、成本、前提】
建议： 【】；原因是【】。

请【决策人】在【日期】前确认选择。未确认前，我会先完成【安全的保底动作】，避免【具体损失】。
```

### 可行性门槛 / Go-No-Go

```text
机会： 【客户/项目】
已确认事实： 【客户问题、决策人、预算、时间、技术输入】
关键假设： 【】
阻断项： 【缺什么就不能承诺什么】
最小验证： 【负责人】-【成本】-【结束日期】-【验收信号】
Go 条件： 【】
No-Go / 暂停条件： 【】
若继续投入：收益【】；机会成本【】；风险接受人【】。
请【决策人】在【日期】前确认【Go/No-Go/补充输入】。
```

### 公开归责后的正式事实说明

```text
主题：补充【事项】的事实、当前风险与下一步

【日期】收到： 【需求/设备/输入】
【日期】完成： 【动作】；结果： 【】
当前阻断项： 【】；依据： 【链接/附件】

为避免后续口径不一致，请【负责人】确认【验收标准/优先级/责任边界】。如以上事实有误，请指出具体条目，我会及时修正。
```

### 一页事实包（正式升级）

```text
事项与请求： 【希望纠正/确认/保护的具体事项】
事实时间线： 【日期—行为—原始来源】
已造成的影响： 【交付/客户/绩效/安全】
已尝试的低冲突解决： 【私下澄清、纪要、资源请求】
当前风险和最晚决策点： 【】
建议处理方案： A【】；B【】。
附件： 【原始邮件/工单/会议纪要/版本记录】
```

## Chat：即时回复、群聊和私信

Chat 目标是：先把话题拉回事实和下一步，不在消息里完成整场辩论。短句、一个问题、一项请求；需要留档时，把链接或“我会后发纪要”放进去。

### 接任务 / 确认边界

```text
我这边先按【目标】推进。
我理解这次交付是【】，截止【】；目前还差【输入/确认】。
这两点没问题的话，我今天先完成【下一步】。
```

### 会后快速对齐

```text
刚才结论我记成三点：
1. 【决定】
2. 【你/我】负责【】；时间【】
3. 还有【风险/待确认】

有不对的地方直接改我，我会后补到项目记录里。
```

### 风险提醒 / 要一个决定

```text
同步一个风险：按现在的【输入/资源】，要在【时间】完成【目标】会影响【】。
我建议选 A【】；如果选 B【】，我也可以按 B 做。
麻烦【决策人】今天【时间】前帮我定一下，我先把【保底动作】做掉。
```

### 被群里拉踩或归责

```text
关于【事项】，我补充下事实：
【日期】收到【输入】；【日期】已完成【动作】；现在卡在【阻断项】，记录在【链接】。

如果上面哪条不对，麻烦直接指出具体位置。下一步需要【负责人】确认【】后我继续推进。
```

### 对方临时改口 / 加范围

```text
收到，这个变化会影响【原计划/交付时间/验收】。
我可以做，但需要一起确认：原来的【】是保留、延期，还是不做？
你定一下优先级，我马上按新顺序排。
```

### 不可能项目 / 先做门槛

```text
这个机会可以先评估，不过现在还缺【预算/接口/决策人/验收】。
我建议先花【时间】做一个小验证，拿到【结果】再决定要不要全量投入；否则现在直接承诺风险比较大。
```

### 供应商或外部承诺变化

```text
供应商这次变更会影响【交期/质量/接口】。
我先整理差异和风险，等【采购/技术/项目】分别确认后再按新方案推进；在确认前，先以【原基线】为准。
```

### 私下澄清，不升级对抗

```text
我想把【具体事情】对一下，避免后面大家理解不一样。
我看到的事实是【】；你那边如果有不同记录，发我一下，我们把统一版本补到项目里。
```

### 聊天后落档

```text
我按刚才确认的【结论】推进，稍后把【纪要/任务卡/风险记录】发出来，后面以那份为准。
```

## 语气校准

- 书面：完整、可追溯、写明责任与日期；不用“你必须”“你之前明明”。
- Chat：像正常同事说话，尽量一屏内说完；不用“如有遗漏请在某时间前指出，否则默认同意”这类法务腔。
- 两种渠道都避免动机判断：写“目前缺少确认”“记录与说法不一致”，不写“你故意甩锅”。
