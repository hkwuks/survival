# Survival：职场兵法 Skill

将中国古代兵法中可正当迁移的判断方法，转化为中国职场里的自保、留痕、交付与决策策略。

它不是“斗人技巧”。目标是把模糊冲突变成可验证的任务：守住交付、边界、信誉与选择权，而不是羞辱或报复同事。

## 适用场景

- 商务抢功、甩锅、公开拉踩或传闻影响信誉
- 不可能项目、供应商变更、客户压力、资源争夺与职责绕过
- 绩效目标反复变化、权责不清、两个领导给出相反指令
- 直属负责人不独立、升级渠道失效，以及需要安全保全或退出
- Chat、邮件、纪要、进度与风险说明的中性表达

## 它会怎么做

复杂情形先判断安全风险、事实和授权，再在五种状态中选择主策略：

- **守**：补齐任务契约、证据与验收基线。
- **势**：以可见交付、固定节奏和共同确认积累可信度。
- **争**：把归责或资源冲突转成有决策人、选项和截止点的事项。
- **变**：通过门槛、试点、替代路径和停止条件改变不可行约束。
- **升/退**：面对霸凌、报复、违法或结构性失效时，优先安全、独立渠道与职业选择。

简单、低风险的措辞请求则使用快捷模式：目标、已知事实、可发送文字、下一步。

## 项目上下文与本地记录

每次分析、决策或同事沟通请求，Skill 会先读取当前项目内可用的设计和变更文档，再将本次用户输入、姓名、原文与证据引用永久记录到项目本地 `survival-records/`。该目录被 `.gitignore` 排除，绝不提交或推送到本仓库；不保存密码、令牌或其他凭据。

## 使用

将本仓库中的 `survival/` 作为 Codex Skill 使用后，可直接描述你的场景，或调用：

```text
$survival：商务在群里说是我导致客户延期，但测试环境和需求一直未确认。我应该怎么回复和留痕？
```

Skill 在复杂场景默认给三段——态势与硬约束、胜算与谁承担后果、可直接发送的回复——并要求每段落到本场景中可被第三方核对的具体对象，写不出的段落不写。给出建议前，先把对方的调整请求（压时间、改范围、转责任、加资源）翻译成我方能验证的对象，再判断哪些谈得了、哪些谈不了。涉及留痕、升级、变局门槛或复盘时按触发表追加对应段落。

## 安全边界

不提供造假、设局、越权取证、泄密、隐私传播、报复、胁迫或操纵他人的方法。涉及暴力、威胁、歧视、性骚扰、欠薪、违法指令、严重报复或商业秘密时，应优先使用正式渠道并寻求当地专业意见。

这不是法律意见，也不能保证具体的劳动争议或职场结果。
